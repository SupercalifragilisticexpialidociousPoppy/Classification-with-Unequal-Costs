\section{Gaussian classifiers (Member~3)}
\label{sec:m3}
\textbf{Code:} \code{models/gaussian.py}, \code{experiments/c2\_gaussian.py}.

The rule needs a spam probability $\post$ for every email. The first model we built gets it by
describing what each class looks like: each class is modelled as a multivariate Gaussian, and Bayes'
rule gives $\post$~\cite[Section~4.2]{bishop2006}. The \emph{shared} model pools one covariance matrix
for both classes, which gives a linear boundary; the \emph{class-specific} model fits one per class,
which gives a quadratic one. On Spambase many features are almost always zero within a class, so the
raw covariances are singular. We shrink them towards a multiple of the identity,
$S\mapsto(1-\alpha)S+\alpha\,\tfrac{\operatorname{tr}S}{d}I$, with $\alpha$ chosen on validation
log-loss. All densities are computed in the log domain from Cholesky factors, without inverting any
matrix. The shared model agrees with scikit-learn's LDA to $10^{-8}$ and the class-specific model with
its QDA to $10^{-6}$.

Word counts are far from Gaussian, so we also tried $\log(1+x)$ before standardising
(Table~\ref{tab:c2}, Figure~\ref{fig:c2}). The transform helps both models. For the shared model the
test log-loss falls from $0.305$ to $0.223$ and the cost with inspection from $0.172$ to $0.143$. The
class-specific model stays far worse with either preprocessing: each class needs its own
$57\times57$ covariance, validation chooses heavy shrinkage ($\alpha\approx0.9$), and $2{,}761$
training emails are not enough to pay for the extra flexibility. Members 5 and 1 therefore use the
shared model with $\log(1+x)$ features on Spambase.
